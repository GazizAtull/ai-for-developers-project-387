# Спецификация: Запись на звонок

Исходная спецификация и обсуждение: https://github.com/GazizAtull/ai-for-developers-project-386/issues/8 (первый проект). Новые изменения заводятся в трекере этого репозитория.

Упрощённый сервис бронирования времени по мотивам Cal.com. Без авторизации, личных кабинетов и внешних календарей.

## Роли
- **Владелец**: один, задан заранее. Заводит типы встреч и смотрит предстоящие записи.
- **Гость**: без регистрации. Выбирает тип, день, время и записывается.

## Правила расписания (приняты в проекте)
| Параметр | Значение |
|---|---|
| Часовой пояс владельца | Asia/Almaty |
| Рабочие дни | пн-пт |
| Рабочие часы | 09:00-18:00 |
| Шаг стартов | 30 минут (09:00, 09:30, ...) |
| Окно записи | 14 календарных дней, начиная с сегодняшнего, сдвигается со временем |
| Длина слота | равна длительности типа встречи |
| Слот должен целиком помещаться в рабочие часы | 60-минутная встреча стартует не позже 17:00 |
| Прошедшее время | недоступно (стартовать можно только в будущем) |

Значения заданы в `ScheduleConfig.defaults()`.

## Тип встречи
Id задаёт владелец: `[a-z0-9-]{1,50}`, уникальный (повтор даёт `409 EVENT_TYPE_EXISTS`). Название (1-100 символов), описание (до 500, необязательно), длительность 5-240 минут, кратна 5.

## Пересечения
- Интервалы полуоткрытые `[start, end)`: следующая встреча может начаться ровно в момент окончания предыдущей.
- Пересечение запрещено между любыми типами встреч, включая частичное наложение.
- Проверка и запись брони выполняются под одним замком, поэтому два одновременных запроса на пересекающееся время не пройдут оба: один получит `201`, остальные `409`.

## API
Контракт: `contract/main.tsp`, из него генерируется `openapi.yaml`.

| Метод | Путь | Назначение | Ошибки |
|---|---|---|---|
| GET | `/api/event-types` | список типов | |
| POST | `/api/event-types` | создать тип (201) | 400 `VALIDATION_ERROR`, 409 `EVENT_TYPE_EXISTS` |
| GET | `/api/event-types/{id}/availability` | свободные слоты на 14 дней, сгруппированы по дням | 404 `EVENT_TYPE_NOT_FOUND` |
| GET | `/api/bookings` | предстоящие встречи всех типов, ближайшие первыми | |
| POST | `/api/bookings` | записаться (201) | 400 `VALIDATION_ERROR` / `SLOT_UNAVAILABLE`, 404 `EVENT_TYPE_NOT_FOUND`, 409 `SLOT_TAKEN` |

Время в ответах: UTC (ISO 8601). Дни в `availability` это даты в часовом поясе владельца; в ответе есть поле `timezone`.

`SLOT_UNAVAILABLE`: время не по сетке, вне рабочих часов, в выходной, в прошлом или за пределами окна.
`SLOT_TAKEN`: слот валиден, но пересекается с существующей записью.

## Запись гостя
Имя (1-100 символов), email и необязательная тема разговора (`topic`). Подтверждений и уведомлений нет.

## Тема разговора
Необязательное поле брони: многострочный plain text до 300 символов. Пробелы по краям обрезаются, внутренние переносы сохраняются; пустое значение после обрезки означает, что темы нет. Тема показывается в подтверждении гостя и в списке предстоящих встреч владельца, если она указана. Брони без темы отображаются как раньше. Тема длиннее 300 символов даёт `400 VALIDATION_ERROR`; конфликт времени с темой по-прежнему `409 SLOT_TAKEN`. Редактирования темы после записи нет.

## Хранение
В памяти процесса. Перезапуск сбрасывает типы встреч и записи (указано также в README).

## SDK и стек
- Контракт на TypeSpec, OpenAPI генерируется `@typespec/openapi3`.
- Клиентский SDK фронтенда генерируется из OpenAPI через `@hey-api/openapi-ts` (`frontend/src/api`).
- Серверного генератора для Spring нет: бэкенд реализован по контракту, совпадение проверяют HTTP-тесты в `ApiContractTest`.
- Бэкенд: Java 21, Spring Boot. Фронтенд: React, Vite, TypeScript. Один Docker-образ: Spring раздаёт собранный фронтенд.
